🖤 Black Screen on Launch
HIGH
Empty canvas with zero onboarding — looks like a crash
The canvas background #0a0a0a + faint #1a1a1a dot grid is intentional, but the dot grid is almost imperceptible (only 10 RGB values apart). A new user seeing a pure black screen has no visual indication the app is alive. Space working confirms React and IPC are functional — the canvas is rendering; it's just empty and invisible.
Fix
Add a centered empty-state overlay rendered on the PixiJS canvas: "Press Space → type open <url>" in JetBrains Mono at --palette-dim color. Disappears once any card is added. Also bump dot grid contrast slightly to #252525.
CRITICAL
PixiJS may silently fail to mount if WebGL is unavailable
PixiJS 8.x defaults to WebGL. On machines with software-only rendering (VMs, RDP sessions, some integrated GPUs), WebGL initialization fails silently, leaving a completely black canvas with no error feedback. The Space key still works because the palette is a React overlay, not PixiJS.
Fix
In PixiCanvas.tsx during PIXI Application init, catch the webglcontextcreationerror event and fall back to PIXI.autoDetectRenderer({ preference: 'canvas' }). Also add a console error log + a visible on-screen message if even Canvas renderer fails.
🌐 URL / Page Loading Issues
CRITICAL
Bare domain (e.g. "instagram") opens blank white page
When you type open instagram, no protocol normalization happens. The Tauri WebviewWindow receives instagram as the URL — which is not valid. WKWebKit/WebView2 navigates to about:blank or an error page that renders as white inside the card.
Fix in commands.ts → open execute()
Normalize the URL before passing to open_card:
if (!url.startsWith('http')) url = 'https://' + url
Then also try appending .com if no TLD is present. Optionally: if the input contains no dots, treat it as a search query and open https://duckduckgo.com/?q={input}.
HIGH
Instagram (and similar sites) actively block non-standard user agents
Even with a correct URL (https://instagram.com), Instagram's server detects the default Tauri/WebKit user-agent string and returns a blank or degraded page. This affects Instagram, Facebook, LinkedIn, and several other JS-heavy SPAs.
Fix in main.rs or tauri.conf.json
Override the User-Agent on the live WebviewWindow to a real Chrome string: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36. In Tauri v2, set via WebviewWindowBuilder::user_agent() in Rust, or the userAgent field in tauri.conf.json windows config.
HIGH
Live WebviewWindow may be positioned at wrong screen coordinates (devicePixelRatio bug)
This is explicitly flagged as Open Question #2 in your own VOID_SPEC.md. The PixiJS canvas works in logical pixels; Tauri positions windows in physical pixels. On a HiDPI display (e.g. 2× retina), the live WebviewWindow will be offset by 2× — the card appears at the correct PixiJS position but the real Tauri window sits twice as far from the top-left. Visually this looks like a white overlay that doesn't align with the card.
Fix in useLiveView.ts + live_view.rs
Get window.devicePixelRatio in the frontend and pass it as part of the IPC payload to focus_card. In Rust, multiply all position/size values by devicePixelRatio before calling .set_position() and .set_size() on the WebviewWindow.
MEDIUM
Navigation within a live card loses URL tracking
The spec doesn't implement a back/forward bar, but also doesn't track URL changes as the user navigates within the live card. When you blur (escape/void), the snapshot is taken and the card's URL in the store is still the original. Restoring the layout later reopens the wrong page.
Fix
In live_view.rs, listen to the WebviewWindow's on_navigation event and emit an IPC event back to the frontend to update the card's URL in the Zustand store before snapshotting.
📸 Snapshot Architecture Issues
CRITICAL
Background refresher WebviewWindow flashes on screen (Windows / WebView2)
Open Question #3 in your spec. On Windows, WebView2 may briefly flash a white or black window even when created with visible: false, because WebView2 renders to a native HWND before the visible flag takes effect. This causes jarring flickers during background snapshot cycling.
Fix for Windows
Create the background refresher window off-screen (e.g. x: -99999, y: -99999) AND with visible: false. Never call show(). Move it back on-screen only for capture_image() if absolutely needed — but test whether capture_image() works off-screen first (it does on macOS/WKWebView; behavior differs on WebView2).
HIGH
Snapshot capture fails silently — card shows blank white sprite
webview.capture_image() in Tauri v2 is experimental and returns Err on some platforms/pages (e.g. pages with Canvas tainting, cross-origin iframes, or GPU-composited content). When it fails, the PNG is never written, and the card sprite either shows the last valid snapshot or remains a blank white rectangle.
Fix in snapshot.rs
Add explicit error handling: if capture_image() returns Err, emit an event to the frontend so the card can display a fallback (e.g. a grey placeholder with the domain name). Log the error. Optionally fall back to injecting html2canvas via eval_script as noted in the spec.
🗃️ Persistence / SQLite Issues
CRITICAL
SQLite plugin not initialized → save/restore crashes silently
tauri-plugin-sql requires explicit initialization in main.rs with .plugin(tauri_plugin_sql::Builder::default().build()) and a DB migration call. If this was generated by Gemini CLI but not verified, the plugin may be registered but the schema may never be created. All save and restore commands would fail without any visible feedback.
Verify in db.rs
Open DevTools (pnpm tauri dev → right-click → Inspect) and run invoke('list_layouts') from the console. If it throws, the DB isn't initialized. Add db::init(&app).await? in main.rs setup and ensure the CREATE TABLE migrations run on first launch.
MEDIUM
Snapshot PNG files not cleaned up on kill
The kill command deletes the card from SQLite, but if close_card in Rust doesn't also delete the snapshot file at {app_data_dir}/void/snapshots/{card_id}.png, dead snapshots accumulate on disk indefinitely.
Fix in card.rs → close_card()
After the DB delete, call std::fs::remove_file(snapshot_path). Wrap in a non-fatal error handler since the file may not exist (cold card that was never snapshot-ed).
⌨️ Command Palette Issues
HIGH
Space key fires inside live card WebviewWindow (double-trigger)
The global Space shortcut is registered at the Tauri level. But when the live card WebviewWindow has focus (user is typing in a web form), pressing Space will both type a space character on the page AND open the command palette, because the Tauri global shortcut intercepts the event before it reaches the page.
Fix in useKeyboard.ts
Instead of using Tauri's global shortcut, intercept Space only on the main canvas window via window.addEventListener('keydown'). Check that the event target is document.body or the canvas element (not an input or the live webview). The live WebviewWindow is a separate OS window, so its key events won't bubble to the canvas anyway — but verify this on all platforms.
MEDIUM
No validation feedback when open command receives invalid URL
Typing open ftp://something or a garbage string creates a card that silently fails to load. The palette closes and nothing happens — no error message, no card, just the empty canvas.
Fix in commands.ts → open
Validate the URL with new URL(normalized) in a try/catch before invoking the Rust command. If invalid, show an inline error in the palette input row (red border + short message) rather than closing the palette.
🎨 Visual / Canvas Issues
MEDIUM
Dot grid doesn't tile correctly at extreme zoom levels
The spec says the dot grid is drawn once and cached as a tiling texture. At zoom < 0.1 or > 2.5, the pre-baked texture either becomes too sparse (zoomed in) or clumps dots together (zoomed out), because the texture tile size was designed for a specific scale range.
Fix in PixiCanvas.tsx
Regenerate the dot grid Graphics object when zoom crosses threshold buckets (e.g. rebuild texture if Math.floor(Math.log2(zoom)) changes). Keep at most 3 cached LOD textures to avoid flicker.
LOW
Card domain label doesn't stay constant screen size at all zoom levels
The spec requires the domain label to remain constant screen-size regardless of zoom (10px, always readable). Achieving this in PixiJS requires inverting the zoom transform on the label's scale: label.scale.set(1 / zoom). If this is missing, the label shrinks to nothing at low zoom.
Fix in CardSprite.ts
Subscribe to zoom changes in the canvas state store. In the zoom update handler, call domainLabel.scale.set(1 / currentZoom) for every visible card sprite.
